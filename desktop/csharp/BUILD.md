# Сборка десктопного приложения ПВ-Система (PVS.exe)

Десктопное приложение = C#-обёртка (окно WebView2) + локальное расчётное
ядро на Python (Flask) + собранный React-интерфейс внутри ядра.

Пользователю отдаётся папка с `PVS.exe` — он запускает её как обычную
программу, интернет не обязателен.

---

## Быстрая сборка одной командой (рекомендуется)

Все шаги ниже автоматизированы в файле `desktop\csharp\build.bat`.
Установи окружение (раздел 0), затем просто запусти:

```cmd
desktop\csharp\build.bat
```

Скрипт сам найдёт корень проекта, проверит окружение и по порядку
выполнит все шаги. При ошибке — остановится и покажет причину.
Готовый результат: `desktop\csharp\dist\` (PVS.exe + server\).

**Ключи запуска** (можно вместе, в любом порядке):

| Ключ | Что делает |
|---|---|
| `resume` | продолжает незаконченную сборку с шага подписи ядра: долгие шаги (интерфейс и компиляция ядра, 15–20 минут) пропускаются. Нужен, если сборка остановилась на подписи — готовое ядро сохраняется и пересобирать его незачем |
| `noobf` | собирает `PVS.exe` без обфускации — чтобы понять, виновата ли в поломке обфускация |

Если сборка найдёт готовое, но **неподписанное** ядро от прошлого запуска, она
сама предложит продолжить с подписи — достаточно нажать Enter.

Разделы ниже — та же сборка вручную по шагам (если нужно понять детали
или собрать что-то отдельно).

## 0. Что нужно установить один раз (окружение сборки)

| Инструмент | Зачем | Ссылка |
|------------|-------|--------|
| Node.js 18+ | собрать React-интерфейс | https://nodejs.org |
| Python 3.11 | собрать расчётное ядро | https://python.org |
| .NET 8 SDK | собрать PVS.exe | https://dotnet.microsoft.com/download/dotnet/8.0 |
| Компилятор C (необязательно) | Nuitka переводит ядро в машинный код | Visual Studio Build Tools 2022 с «Разработка классических приложений на C++»; если их нет, сборка один раз скачает MinGW64 (~380 МБ, с докачкой) в `%LOCALAPPDATA%\PVSnk` |

### Закрытый ключ подписи ядра

Им подписывается `server.exe`; без подписи `PVS.exe` ядро не запустит.

**Где взять.** Помнить и копировать ключ не нужно: значение секрета
`OFFLINE_KEY_PRIVATE` в интерфейсе poehali.dev скрыто. На шаге подписи сборка
спросит **пароль администратора** (тот же, что от панели `/admin`) и сама
получит ключ из облака. Ключ не показывается и не сохраняется.

**Как передать сборке** — любой способ на выбор:

| Способ | Что сделать | Когда удобно |
|---|---|---|
| Пароль администратора | запустить `build.bat`, на шаге подписи ввести пароль от `/admin` (правой кнопкой мыши, вместо символов — звёздочки) | обычный случай |
| Вставить сам ключ | на шаге подписи нажать Enter вместо пароля и вставить ключ | если ключ под рукой |
| Навсегда | один раз `setx OFFLINE_KEY_PRIVATE "<значение>"`, затем открыть **новое** окно | постоянная машина сборки |


Ключ нигде не сохраняется и никуда не отправляется — им только подписывается
`server.exe` на этой машине. Не храните его в файлах рядом с проектом.

Проверить ключ, ничего не собирая:

```cmd
python desktop\csharp\sign_core.py --check
```

Сборка делает эту же проверку в самом начале (шаг 0), чтобы неподходящий ключ
не всплыл после 20 минут компиляции. Если ключ не задан вовсе — это не ошибка:
сборка идёт дальше и спросит его на шаге подписи.

Проверить, что всё установлено:

```cmd
node -v
python --version
dotnet --version
```

Дальше во всех командах считается, что проект лежит в `C:\PVS`.
Замени путь на свой, если он другой.

## Шаг 1 — Собрать интерфейс (⚠️ КЛЮЧЕВОЙ ШАГ, без него не работает активация)

> ⚠️ ОБЯЗАТЕЛЬНО собирать именно этой командой (desktop-режим).
> Она включает флаг десктопа и направляет запросы на локальное ядро
> `http://127.0.0.1:5173/api/...`.
>
> Если собрать обычной `npm run build` — ключ активации НЕ примется,
> появится ошибка `Unexpected token '<', "<!doctype"...`, а расчёты и
> кнопки окна работать не будут.

```cmd
cd C:\PVS

npm install
node_modules\.bin\vite build --config vite.config.desktop.ts
```

> ⚠️ Собирай именно через `node_modules\.bin\vite` — это локальный vite
> проекта (специальная сборка rolldown-vite). НЕ используй `npx vite` —
> он попытается скачать чужую версию vite и спросит подтверждение,
> сборка получится неправильной.

Результат появится в папке `dist-desktop`. Переносим его в расчётное ядро:

```cmd
rmdir /S /Q desktop\pywebview\pvs-core\dist
xcopy /E /I /Y dist-desktop desktop\pywebview\pvs-core\dist
```

После этого должен существовать файл:
`desktop\pywebview\pvs-core\dist\index.html`

## Шаг 2 — Собрать расчётное ядро server.exe (Nuitka) и подписать его

### Защита ядра

* **Машинный код вместо байт-кода.** Раньше ядро упаковывалось PyInstaller
  в байт-код `.pyc`. Бесплатные утилиты распаковывают такой `server.exe` и
  восстанавливают читаемый Python за минуты — вместе с проверкой лицензии.
  Теперь Nuitka переводит Python в C и компилирует в машинный код: исходников
  и байт-кода внутри нет, восстановить логику можно только дизассемблированием.
* **Подпись при каждом запуске.** `sign_core.py` считает SHA-256 готового
  `server.exe` и подписывает её закрытым ключом Ed25519 (`server.sig`).
  `PVS.exe` перед каждым запуском ядра сверяет сумму файла и подпись
  публичным ключом. Изменённое ядро не запустится: программа попробует
  скачать подлинное, а без интернета покажет ошибку. Во время работы файл
  ядра держится открытым, поэтому подменить его на ходу нельзя.

### Команды

```cmd
cd C:\PVS\desktop\csharp
python -m pip install -r requirements-build.txt

REM 1) разложить ядро и расчётные функции для Nuitka (bf_<имя>.py)
python prepare_core.py ..\pywebview\pvs-core ..\..\backend server_entry.py pvs-core-nuitka

REM 2) скомпилировать (5–20 минут; список модулей — в pvs-core-nuitka\modules.txt,
REM    build.bat подставляет его сам)
cd pvs-core-nuitka
python -m nuitka --onefile --assume-yes-for-downloads --windows-console-mode=disable ^
  --output-dir=..\nuitka-build --output-filename=server.exe ^
  --include-data-dir=dist=dist --include-module=server ^
  --include-module=bf_airflow --include-module=license_guard ^
  ... (остальные модули из modules.txt) ^
  server_entry.py
cd ..

REM 3) разложить и подписать
mkdir dist\server
copy nuitka-build\server.exe dist\server\server.exe
python sign_core.py dist\server\server.exe
```

Проще запустить `build.bat` — он делает всё это сам.

### Публикация обновления ядра

Загрузи `dist\server\server.exe` и опубликуй его в админ-панели
(«Обновление»), как раньше. Облако посчитает сумму и подпишет её тем же
ключом, а программа при обновлении сохранит подпись рядом с ядром
(`server.sig`) и будет проверять её при каждом запуске.

> ⚠️ Устанавливай программу только вместе с `server.sig`: установщик
> берёт всю папку `server\`, поэтому при сборке через `build.bat` файл
> подписи попадает туда автоматически.

## Шаг 3 — Иконка окна и панели задач (pvs.ico)

Готовая иконка из логотипа ПВ-Система уже сгенерирована (размеры
16/32/48/64/128/256 в одном файле). Скачай её в проект одной командой:

```cmd
curl -o C:\PVS\desktop\csharp\PvsApp\pvs.ico ^
  https://cdn.poehali.dev/projects/564c75d6-cb0f-4378-9852-c88803b7dcf2/bucket/icons/desktop-icon.ico
```

(или просто открой ссылку в браузере и сохрани файл как
`desktop\csharp\PvsApp\pvs.ico`)

Ссылка на иконку:
https://cdn.poehali.dev/projects/564c75d6-cb0f-4378-9852-c88803b7dcf2/bucket/icons/desktop-icon.ico

`.csproj` подхватит `pvs.ico` автоматически (иконка подключается только
если файл существует). Если файла нет — программа всё равно соберётся,
но со стандартной иконкой Windows.

> ⚠️ Если иконка выглядит **размытой** на рабочем столе / в меню Пуск,
> хотя файл `pvs.ico` на месте — почти всегда виноват **кэш иконок Windows**
> (система показывает старую растянутую картинку). После пересборки
> выполни один раз в командной строке:
>
> ```cmd
> ie4uinit.exe -show
> taskkill /IM explorer.exe /F & start explorer.exe
> ```
>
> Иконка `pvs.ico` содержит все нужные размеры (16/32/48/64/128/256),
> поэтому после сброса кэша Windows покажет её чётко в любом масштабе.
> Если заменял `.exe` в уже установленной программе — на всякий случай
> удали старый ярлык и создай заново (правый клик по `PVS.exe` →
> «Отправить» → «Рабочий стол»).

## Шаг 3.1 — Иконка файлов-схем .vproj (vproj.ico)

Отдельная **качественная** иконка документа для файлов `.vproj` (чтобы
файлы-схемы в проводнике выглядели чётко, а не размытой копией иконки
программы). Уже лежит в репозитории:

- `desktop\csharp\PvsApp\vproj.ico` — готовый многоразмерный ICO (16…256);
- `desktop\csharp\PvsApp\vproj_src.png` — исходник, из которого `build.bat`
  пересобирает ICO командой `make_ico.py` (Шаг 3 сборки).

Ассоциация `.vproj` (иконка + открытие по двойному клику) прописывается
установщиком `pvs_installer.iss` в разделе `[Registry]`:

- `PVS.Project\DefaultIcon` → `{app}\vproj.ico` (иконка документа);
- `PVS.Project\shell\open\command` → `"PVS.exe" "%1"` — двойной клик по
  файлу запускает программу **и передаёт путь к файлу**, схема открывается
  сразу.

> ⚠️ Если после установки файлы `.vproj` всё ещё показывают старую иконку —
> это **кэш иконок Windows**. Сбрось его так же, как в примечании выше:
> `ie4uinit.exe -show` + перезапуск `explorer.exe`.
>
> ⚠️ Если двойной клик по-прежнему просто открывает программу без схемы —
> значит установлена **старая версия** (ассоциация без `"%1"`). Переустанови
> актуальным `PVS-Setup-*.exe` — новый установщик перезапишет ассоциацию.

## Шаг 4 — Собрать PVS.exe (C#) с обфускацией

Код C# защищается от декомпиляции обфускатором **Obfuscar** (бесплатный).
После обфускации имена классов/методов/полей и строковые константы
становятся нечитаемыми в dnSpy/ILSpy. Сборка идёт в 3 подшага:
компиляция → обфускация `PVS.dll` → упаковка в один `.exe`.

```cmd
cd C:\PVS\desktop\csharp\PvsApp

REM 1) компиляция (получаем обычную PVS.dll, ещё без упаковки)
dotnet build -c Release -r win-x64 --self-contained true ^
  -p:PublishSingleFile=false ^
  -o bin\Release\net8.0-windows\win-x64

REM 2) установка обфускатора (один раз) и обфускация PVS.dll
dotnet tool install --tool-path ..\.tools Obfuscar.GlobalTool
..\.tools\obfuscar.console.exe ^
  -var InPath="%CD%\bin\Release\net8.0-windows\win-x64" ^
  -var OutPath="%CD%\bin\Release\net8.0-windows\win-x64\obf" ^
  obfuscar.xml
copy /Y bin\Release\net8.0-windows\win-x64\obf\PVS.dll ^
        bin\Release\net8.0-windows\win-x64\PVS.dll

REM 3) упаковка БЕЗ пересборки (--no-build), чтобы взялась обфусцированная dll
dotnet publish -c Release -r win-x64 --self-contained true --no-build ^
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true ^
  -o ..\dist
```

> ⚠️ Ключевой момент — шаг 3 идёт с флагом `--no-build`. Без него
> `dotnet publish` пересобрал бы проект заново и **стёр обфускацию**.
>
> Настройки обфускации — в файле `PvsApp\obfuscar.xml`. Типы `App` и
> `MainWindow` исключены из переименования, т.к. WPF обращается к ним
> по имени через XAML (иначе окно перестанет работать).

Всё это уже автоматизировано в `build.bat` (Шаг 4) — при обычной сборке
ничего вручную делать не нужно.

## Проверка, что всё собралось правильно (чек-лист)

1. Запусти `PVS.exe`.
2. Появляется заставка «Запуск расчётного ядра…», затем интерфейс.
3. Открой окно активации → введи ключ → нажми «Активировать лицензию».
   - ✅ Правильно: ключ принимается либо приходит понятный ответ сервера.
   - ❌ Ошибка `Unexpected token '<'` = интерфейс собран не desktop-режимом.
     Вернись к Шагу 1 и пересобери.
4. Кнопки в правом верхнем углу (свернуть / развернуть / закрыть) работают.
5. Логотип отображается в шапке и в окне «О программе».
6. (Опционально) Открой `PVS.dll` из `dist` в dnSpy — имена методов/полей
   должны быть нечитаемыми (обфускация C# сработала).
7. Расчёты работают (аэродинамика, взрыв) — значит ядро, скомпилированное
   Nuitka, запускается корректно.
8. Проверка подписи: измени один байт в `server\server.exe` (или удали
   `server\server.sig`) и отключи интернет — программа должна отказаться
   запускаться с сообщением «Расчётное ядро повреждено, изменено или не
   найдено». Причина пишется в `%LOCALAPPDATA%\PVS\update.log`.

## Частые ошибки

| Симптом | Причина | Решение |
|---------|---------|---------|
| `Unexpected token '<'` при активации | интерфейс собран обычной `npm run build` | пересобрать Шагом 1 (desktop-конфиг) |
| «Ошибка активации» при верном ключе | старый `server.exe` со старым адресом лицензии | пересобрать ядро (Шаг 2) — адрес лицензии зашит в `server.exe` |
| «Не удалось запустить расчётный модуль» | нет `server\server.exe` рядом с `PVS.exe` | проверить Шаг 2 |
| «airflow модуль не найден» | backend-функции не скопированы в ядро | выполнить копирование в начале Шага 2 и пересобрать |
| Пустое белое окно | не скопирован `dist` в `pvs-core\dist` | повторить конец Шага 1 |
| Логотип-«битая картинка» без сети | нормально: оффлайн подставляется запасной значок | это ожидаемо |
| Иконка окна стандартная | нет `pvs.ico` | выполнить Шаг 3 |
| Окно не открывается / падает после обфускации | WPF-тип переименован | добавить его в `<SkipType>` в `PvsApp\obfuscar.xml` и пересобрать |
| `obfuscar.console.exe not found` | не установился инструмент Obfuscar | проверить интернет/доступ к nuget.org, повторить Шаг 4 |
| Обфускация «не применилась» | publish пересобрал проект | шаг 3 публикации должен идти с `--no-build` |
| «Расчётное ядро повреждено, изменено или не найдено» | нет `server.sig` или ядро пересобрано без новой подписи | `desktop\csharp\build.bat resume` — допишет подпись без пересборки |
| «этот закрытый ключ не подходит к программе» | вставлен не тот ключ или не целиком | получить ключ по паролю администратора на шаге подписи |
| «значение не похоже на закрытый ключ Ed25519» | в ключ попали пробелы/переносы или скопирован не тот текст | скопировать значение секрета заново, одной строкой |
| «server.exe is NOT signed» в конце сборки | ключ не введён | ядро уже скомпилировано — подписать его отдельно: `python desktop\csharp\sign_core.py desktop\csharp\dist\server\server.exe`, пересобирать не нужно |
| Nuitka: `No module named bf_...` / «модуль не найден» | модуль не попал в `--include-module` | проверить `pvs-core-nuitka\modules.txt`; новый файл функции должен лежать рядом с её `index.py` |
| Nuitka просит компилятор / долго качает | нет Visual Studio C++ | дождаться загрузки MinGW64 (один раз, ~380 МБ) или поставить Build Tools |
| `Problem with the downloaded zip file` / `need 'mingw64\bin\gcc.exe'` | архив MinGW64 скачался не полностью (обрыв, прокси, антивирус) | сборка теперь качает его сама с докачкой (`prepare_compiler.py`) — просто запустить `build.bat` ещё раз. Если GitHub недоступен — скачать архив браузером по ссылке из сообщения и положить в указанную папку, либо поставить Visual Studio Build Tools 2022 с C++ |
| Антивирус удаляет `server.exe` | эвристика на onefile-сборки | добавить папку сборки в исключения; для пользователей — подписать установщик сертификатом |

## Требования на компьютере пользователя

- Windows 10/11 x64
- WebView2 Runtime (в Windows 11 уже есть; для Windows 10:
  https://go.microsoft.com/fwlink/p/?LinkId=2124703)
- .NET Runtime НЕ нужен (собрано self-contained)
- Python НЕ нужен
- Интернет НЕ обязателен (кроме первичной онлайн-проверки лицензии)
