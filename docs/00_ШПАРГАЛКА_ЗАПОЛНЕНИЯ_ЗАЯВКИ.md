## ШАГ 3/13. ОПИСАНИЕ ПРОГРАММНОГО ОБЕСПЕЧЕНИЯ

### Краткое описание программного обеспечения

```
«ПВ-Система» — программный комплекс класса САПР для проектирования,
компьютерного моделирования и инженерного расчёта систем вентиляции
и противопожарного водоснабжения подземных горных выработок шахт
и рудников.

Программа обеспечивает построение графовой модели вентиляционной сети
горных выработок, расчёт распределения воздушных потоков методом
контурных расходов (метод Хэрди-Кросса) на основе законов Кирхгофа,
расчёт аэродинамического сопротивления выработок, подбор вентиляторов
главного и местного проветривания, моделирование аварийных
вентиляционных режимов при подземных пожарах и взрывах, гидравлический
расчёт пожарно-оросительного водоснабжения, а также расчёт маршрутов
горноспасательных отделений и подготовку материалов планов ликвидации
аварий (ПЛА).

Программа предназначена для проектных и научно-исследовательских
организаций горного профиля, служб аэрологической безопасности
и вентиляции горнодобывающих предприятий, военизированных
горноспасательных частей.

Программа поставляется в виде настольного приложения для ОС Windows
и веб-приложения. Язык интерфейса и документации — русский.
```

### Функциональные характеристики программного обеспечения

```

1. Построение и редактирование графовой модели вентиляционной сети
из узлов и ветвей с трёхмерными координатами, привязкой к горизонтам,
заданием геометрии выработок (круглое, прямоугольное, трапецеидальное,
арочное, произвольное сечение) и типов крепи.

2. Расчёт аэродинамического сопротивления выработок четырьмя способами:
по коэффициенту аэродинамического сопротивления (формула Аткинсона
R = α·L·P/S³), по типу крепи с использованием встроенного справочника
(11 типов поверхностей), по эквивалентной шероховатости (формула
Альтшуля), прямым вводом по данным воздушно-депрессионной съёмки.
Расчёт вентиляционных трубопроводов по формуле R = 6,48·α·L/D⁵
со справочником из 7 типов труб и гибких рукавов.

3. Расчёт воздухораспределения в сети произвольной сложности методом
контурных расходов (метод Хэрди-Кросса) на основе законов Кирхгофа
с итерационным решением системы нелинейных уравнений, контролем
сходимости по расходу и депрессии (до 5000 итераций), учётом
естественной тяги, влажности, барометрического давления
и геотермического градиента.

4. Каталог вентиляторов главного, вспомогательного и местного
проветривания с напорными и энергетическими характеристиками,
включающий машины отечественного производства (ВЦ-15, ВЦ-25,
ВЦД-31,5, ВЦД-32, ВЦД-47У, ВО-18/12АВР, ВОД-16АВ, ВОД-21, ВОД-30,
ВОД-40 и другие). Определение рабочей точки как пересечения
характеристики вентилятора с характеристикой сети, расчёт КПД
и потребляемой мощности, учёт угла установки лопаток, частоты
вращения, реверсивного режима, параллельной и последовательной
работы вентиляторов.

5. Моделирование аварийных режимов при подземном пожаре: расчёт
тепловой депрессии, оценка риска опрокидывания вентиляционной струи,
расчёт остывания продуктов горения с учётом теплообмена с породным
массивом, распространение оксида и диоксида углерода и дыма по сети,
определение зон задымления и дальности видимости. Справочник
пожарной нагрузки из 7 типов материалов.

6. Расчёт параметров ударной воздушной волны при взрыве по методике
Садовского с определением избыточного давления во фронте волны
и границ зон поражения, со справочником взрывчатых веществ.

7. Гидравлический расчёт пожарно-оросительного водоснабжения
по формуле Дарси-Вейсбаха с моделированием трубопроводов, насосов,
регуляторов давления и водопотребителей (пожарных стволов,
оросителей, пеногенераторов).

8. Расчёт оптимальных маршрутов передвижения отделений ВГСЧ
по алгоритму Дейкстры с учётом нормативных скоростей передвижения,
углов наклона выработок, задымления и расхода кислорода дыхательных
аппаратов. Расстановка и нумерация позиций плана ликвидации аварий.

9. Двумерная и трёхмерная визуализация схемы в видах «План», «Фронт»,
«Профиль» с цветовой раскраской по расходу, скорости, депрессии,
направлению движения воздуха и горизонтам, управлением видимостью
слоёв и раздельным масштабированием по осям.

10. Аналитические функции: построение депрессиограммы, сводный расчёт
потребного количества воздуха по забоям, проверка устойчивости
проветривания при пожаре, расчёт пожарно-оросительного трубопровода,
определение зоны поражения и условий вывода людей, обработка данных
воздушно-депрессионной съёмки с расчётом эквивалентного отверстия,
сравнение вариантов схем.

11. Импорт данных из электронных таблиц Excel, файлов CSV, чертежей
DXF, файлов XML и текстовых файлов, а также из файлов сторонних систем
моделирования вентиляции. Экспорт результатов в Microsoft Excel,
CSV, PDF, SVG. Хранение проектов в собственном формате .vproj
с регистрацией файловой ассоциации.

12. Лицензирование с онлайн-активацией и автономным ключом
на основе криптографической электронной подписи для рабочих мест
без доступа в сеть Интернет, административная панель управления
лицензиями, встроенный механизм обновления.
```

## ШАГ 6/13. СВЕДЕНИЯ О ПРОГРАММНЫХ МОДУЛЯХ

**Ничего не добавлять — шаг пропустить, нажать «Дальше».**

Этот раздел заполняется только тогда, когда в состав заявляемого ПО входят **отдельные программные модули, которые самостоятельно включаются в реестр** (например, вы заявляете платформу, а её модули регистрируются как отдельные продукты со своими реестровыми записями).

«ПВ-Система» — **единый неделимый продукт**. Расчётное ядро, серверные функции и настольная оболочка не являются самостоятельными программами: по отдельности они неработоспособны, не поставляются и не лицензируются. Поэтому модули не указываются.

> Не путайте с функциональными блоками программы (расчёт пожара, гидравлика, ПЛА). Они уже описаны на шаге 3/13 как функциональные характеристики и повторно как «модули» не заявляются. Лишние записи здесь создадут расхождение с описанием и вызовут вопросы эксперта.

> ⚠️ **Это единственные каналы связи по заявлению.** Все уведомления, замечания эксперта и требования о доработке придут именно на эту почту. Пропущенное письмо = отказ по формальному основанию. Не указывайте почту, доступ к которой может быть утрачен.

### Документ, подтверждающий полномочия лица, подписавшего заявление

Порядок зависит от того, **кто является правообладателем**:

**Вариант А. Правообладатель — вы как физическое лицо (или ИП), и вы же подаёте заявление.**

Документ о полномочиях **не требуется** — вы действуете от собственного имени. Поле можно оставить незаполненным.

**Вариант Б. Правообладатель — юридическое лицо, и вы его руководитель.**

Приложить PDF-документ, подтверждающий полномочия единоличного исполнительного органа:
- решение (протокол) о назначении руководителя;
- либо приказ о вступлении в должность;
- либо актуальная выписка из ЕГРЮЛ, где вы указаны как лицо, действующее без доверенности.

**Вариант В. Правообладатель — юридическое лицо, а вы действуете по доверенности.**

Приложить доверенность на подачу заявления и совершение действий от имени правообладателя. При использовании машиночитаемой доверенности отметить галочку **«Машиночитаемая доверенность в XML-формате»** и приложить XML.

> На скриншоте заявителем указано **физическое лицо**. Если правообладателем ПО заявляется это же физическое лицо — действует вариант А, и загружать ничего не нужно.

## ШАГ 8/13. СВЕДЕНИЯ О ПРАВООБЛАДАТЕЛЯХ

Нажать **«Добавить правообладателя»** и внести данные того, кому принадлежит исключительное право.

### Если правообладатель — физическое лицо (или ИП)

| Поле | Значение |
|---|---|
| Тип правообладателя | Физическое лицо / индивидуальный предприниматель |
| ФИО | Полностью, как в паспорте |
| ИНН | Ваш ИНН |
| Гражданство | Российская Федерация |
| Доля в исключительном праве | **100 %** |
| Контактные данные | Телефон, электронная почта, адрес |

### Если правообладатель — юридическое лицо

| Поле | Значение |
|---|---|
| Тип правообладателя | Юридическое лицо |
| Полное наименование | Как в уставе и ЕГРЮЛ |
| ИНН / ОГРН / КПП | Из выписки ЕГРЮЛ |
| Юридический адрес | Как в ЕГРЮЛ |
| Доля в исключительном праве | **100 %** |

### Ключевые требования, которые проверяет эксперт

- **Суммарная доля всех правообладателей должна составлять ровно 100 %.** При одном правообладателе — 100 %.
- Для **юридического лица**: суммарная доля прямого и (или) косвенного участия иностранных лиц не должна превышать **50 %**.
- Для **физического лица**: гражданство Российской Федерации.
- Данные должны **дословно совпадать** с ЕГРЮЛ/ЕГРИП и с документами, прилагаемыми на шаге 9.

> ⚠️ Если правообладателей несколько (например, соавторы), каждого нужно добавить отдельно с указанием его доли, а на шаге 9 приложить соглашение о распределении долей в исключительном праве.

## ШАГ 9/13. ИСКЛЮЧИТЕЛЬНОЕ ПРАВО

Самый ответственный шаг: здесь подтверждается, что право на программу действительно принадлежит вам **на территории всего мира и на весь срок действия исключительного права**.

### Сведения об основаниях возникновения исключительного права

Выберите формулировку, соответствующую вашей ситуации.

**Вариант А. Программа создана лично автором-правообладателем (физическим лицом).**

```
Исключительное право на программу для ЭВМ «ПВ-Система» принадлежит
[ФИО полностью], гражданину Российской Федерации, ИНН [__________],
в полном объёме (100 %).

Основание возникновения исключительного права — создание произведения
творческим трудом автора (статьи 1228, 1257, 1259, 1261 и 1295
Гражданского кодекса Российской Федерации). Программа создана автором
самостоятельно, не по заказу и не в порядке выполнения служебного
задания.

Исключительное право действует на территории всего мира и в течение
всего срока действия исключительного права. Программа не обременена
правами третьих лиц: лицензионные договоры, договоры об отчуждении
исключительного права, договоры залога и иные соглашения, ограничивающие
распоряжение исключительным правом, не заключались.

Программа для ЭВМ зарегистрирована в Федеральной службе по
интеллектуальной собственности (Роспатент), свидетельство
о государственной регистрации программы для ЭВМ
№ [__________] от [__.__.____].
```

> Последний абзац включать **только при наличии свидетельства**. Если регистрации нет — абзац удалить, а поля «Номер государственной регистрации» и «Дата государственной регистрации» оставить пустыми.

**Вариант Б. Программа создана работниками организации (служебное произведение).**

```
Исключительное право на программу для ЭВМ «ПВ-Система» принадлежит
[полное наименование организации], ИНН [__________], ОГРН [__________],
в полном объёме (100 %).

Основание возникновения исключительного права — создание программы
работниками правообладателя в пределах установленных для них трудовых
обязанностей (служебное произведение, статья 1295 Гражданского кодекса
Российской Федерации). Исключительное право на служебное произведение
принадлежит работодателю.

Исключительное право действует на территории всего мира и в течение
всего срока действия исключительного права. Программа не обременена
правами третьих лиц.
```

**Вариант В. Право приобретено по договору об отчуждении исключительного права.**

```
Исключительное право на программу для ЭВМ «ПВ-Система» принадлежит
[наименование / ФИО правообладателя] в полном объёме (100 %)
на основании договора об отчуждении исключительного права
№ [_____] от [__.__.____], заключённого с [наименование / ФИО
первоначального правообладателя].

По условиям договора исключительное право передано приобретателю
в полном объёме, на территории всего мира и на весь срок действия
исключительного права. Обязательства по договору исполнены сторонами
в полном объёме, что подтверждается актом приёма-передачи
от [__.__.____].
```

### Номер и дата государственной регистрации

Заполняются **только при наличии свидетельства Роспатента** на программу для ЭВМ. Поля необязательные — при отсутствии регистрации оставить пустыми.

> Свидетельство Роспатента не является обязательным условием включения в реестр, но резко снижает риск замечаний: оно само по себе служит доказательством авторства и принадлежности права. Если планируете подавать заявление не срочно — имеет смысл сначала получить свидетельство (срок регистрации порядка 2 месяцев).

### Документы, подтверждающие основания возникновения исключительного права

Прилагаемый комплект зависит от выбранного варианта:

| Ситуация | Какие документы приложить |
|---|---|
| Вариант А (личное творчество) | Свидетельство Роспатента (при наличии). При отсутствии — заявление автора о создании программы личным творческим трудом с описанием обстоятельств создания, приложением сведений об истории разработки (даты, этапы) |
| Вариант Б (служебное произведение) | Трудовые договоры (или выписки) с работниками-авторами, должностные инструкции либо служебные задания, акты приёмки созданных программ, приказ о введении в эксплуатацию |
| Вариант В (отчуждение права) | Договор об отчуждении исключительного права, акт приёма-передачи, документы об оплате |
| Несколько правообладателей | Дополнительно — соглашение о распределении долей в исключительном праве |

**Описание файла** (в поле перед загрузкой) укажите содержательно, например:

```
Свидетельство о государственной регистрации программы для ЭВМ
«ПВ-Система» № ______ от __.__.____
```

> ⚠️ Загруженный документ должен **подтверждать всё заявленное в текстовом поле**. Расхождение между описанием оснований и приложенными документами — самая частая причина возврата заявления на доработку.

## ОБЩИЕ ЗАМЕЧАНИЯ ПО ПОДАЧЕ

1. **Заявление подписывается усиленной квалифицированной электронной подписью** — правообладателя-физического лица лично либо руководителя организации-правообладателя (или уполномоченного лица по доверенности).

2. **Требования к правообладателю:** российское юридическое лицо с долей иностранного участия не более 50 % либо российский гражданин / индивидуальный предприниматель.

3. **Выплаты по лицензионным договорам иностранным лицам** не должны превышать 30 % выручки от реализации ПО за год.

4. **Свидетельство о государственной регистрации программы для ЭВМ** (Роспатент) не обязательно, но существенно упрощает подтверждение прав. Рекомендуется получить до подачи.

5. **Проверьте доступность всех ссылок** из заявления из внешней сети без авторизации.

6. Сохраняйте заявление кнопкой **«Сохранить»** на каждом шаге — форма длинная.

7. Срок рассмотрения — до 65 рабочих дней. При замечаниях эксперта заявление возвращается на доработку, срок отсчитывается заново.
