# ПВ-Система — полное резервное зеркало на Beget

Это полная копия программы на вашем сервере, которая работает без poehali.dev:

- сайт с программой: схемы и все расчёты;
- админ-панель `/admin`: лицензии, аварийные ключи, рабочие места, мониторинг, клиентские доступы;
- кабинет клиента `/client`, страница скачивания `/download`;
- выдача и проверка лицензий;
- своя база PostgreSQL. В неё копируются все лицензии из облака.

> Резервный расчётный сервер из папки `backup-server` только считает.
> Лицензий и админ-панели в нём нет. Для полного резерва используйте эту папку.

---

## Почему нужен VPS, а не обычный хостинг

Программе нужна база PostgreSQL и постоянно работающий Python-процесс.
На виртуальном хостинге Beget есть только MySQL, а постоянные процессы там не держатся.
Поэтому нужен **облачный VPS Beget**: от 1 ядра, 2 ГБ ОЗУ и 15 ГБ диска, образ **Ubuntu 22.04 или 24.04**.

---

## Шаг 1. Заказать VPS

1. Панель Beget → **Облако / VPS** → «Создать сервер».
2. Выберите ОС **Ubuntu 24.04**, 1 CPU, 2 ГБ RAM (можно больше), 15 ГБ диска.
3. Задайте root-пароль или добавьте SSH-ключ.
4. Запишите **IP-адрес** сервера.

## Шаг 2. Направить домен на VPS

Панель Beget → **DNS** → у нужного домена создайте поддомен, например
`reserv.ваш-домен.ru`, и добавьте **A-запись** с IP-адресом VPS.
Подождите 5–30 минут, пока запись разойдётся.

> Кириллический домен (`резерв.пв-система.рф`) тоже работает.
> В командах ниже пишите его в punycode (`xn--...`). Получить punycode можно на любом онлайн-конвертере.

## Шаг 3. Загрузить программу на VPS

Подключитесь к серверу:
- Windows: PowerShell, команда `ssh root@IP-АДРЕС`;
- или веб-консоль в панели Beget.

```bash
apt-get update && apt-get install -y git
git clone https://github.com/ВАШ-ЛОГИН/ВАШ-РЕПОЗИТОРИЙ.git /opt/pvs
```

Если репозиторий закрытый, Git попросит логин. Вместо пароля вставьте
GitHub-токен: GitHub → Settings → Developer settings → Personal access tokens.

## Шаг 4. Запустить автоустановку

```bash
bash /opt/pvs/mirror-server/deploy/install.sh reserv.ваш-домен.ru ваша@почта.ru
```

Установка идёт 10–15 минут. Скрипт сам:
- ставит PostgreSQL, Python, Node.js и nginx;
- создаёт базу `pvs` и все таблицы;
- собирает сайт;
- запускает службу `pvs-mirror`;
- выпускает бесплатный SSL-сертификат Let's Encrypt.

## Шаг 5. Вписать секреты — это обязательно

```bash
nano /opt/pvs/mirror-server/.env
```

Заполните две строки. Значения возьмите в poehali.dev: **Настройки проекта → Секреты**.

| Строка | Откуда взять |
|---|---|
| `ADMIN_PASSWORD=` | секрет `ADMIN_PASSWORD`, пароль админ-панели |
| `OFFLINE_KEY_PRIVATE=` | секрет `OFFLINE_KEY_PRIVATE`, ключ подписи лицензий |

⚠️ `OFFLINE_KEY_PRIVATE` должен совпадать **символ в символ**.
Его публичная половина зашита в программу. С другим ключом выданные
лицензии и аварийные ключи не пройдут проверку.
**Сохраните этот ключ отдельно в надёжном месте прямо сейчас:**
если poehali.dev будет недоступен, достать его оттуда не получится.

Сохраните файл (Ctrl+O, Enter, Ctrl+X) и перезапустите службу:

```bash
systemctl restart pvs-mirror
```

## Шаг 6. Перенести лицензии из облака

```bash
/opt/pvs/mirror-server/.venv/bin/python /opt/pvs/mirror-server/sync_from_cloud.py
```

Скрипт выведет таблицы и количество строк, в конце напишет «Готово».
Будут перенесены лицензии, рабочие места, аварийные ключи, клиентские
доступы, журнал событий, настройки и номер версии программы.

Скрипт работает, только пока облачная база poehali.dev доступна.
Если облако не ответило, база зеркала **не изменяется**.

## Шаг 7. Включить автосинхронизацию

Добавьте синхронизацию по расписанию, чтобы в момент аварии на зеркале были свежие лицензии:

```bash
crontab -e
```

Добавьте строку (синхронизация каждый час):

```
0 * * * * /opt/pvs/mirror-server/.venv/bin/python /opt/pvs/mirror-server/sync_from_cloud.py >> /var/log/pvs-sync.log 2>&1
```

⚠️ **Важно.** Синхронизация полностью заменяет базу зеркала облачной копией.
Пока работаете на зеркале (во время аварии), **отключите эту строку**:
поставьте `#` в начале строки. Иначе после восстановления облака
лицензии, выданные на зеркале, затрутся.

## Шаг 8. Проверить

| Адрес | Что должно быть |
|---|---|
| `https://reserv.ваш-домен.ru/health` | `"ok": true`, `"database": "ok, licenses=N"`, все функции `true` |
| `https://reserv.ваш-домен.ru/` | программа открывается |
| `https://reserv.ваш-домен.ru/admin` | вход по тому же паролю, видны все лицензии |

---

## Что делать при аварии poehali.dev

1. Отключите автосинхронизацию: `crontab -e` → `#` перед строкой.
2. Сообщите пользователям новый адрес: `https://reserv.ваш-домен.ru/`.
3. Лицензии продолжают действовать: ключи, места и подписи те же.
   Если у пользователя обновилась привязка браузера, он один раз вводит свой ключ заново.
4. Новые ключи выдавайте в админ-панели зеркала.

Когда poehali.dev восстановится, новые ключи, выданные на зеркале,
нужно вручную завести в облачной админ-панели. Только после этого
снова включайте автосинхронизацию.

## Обновление зеркала после изменений в программе

```bash
bash /opt/pvs/mirror-server/deploy/update.sh
```

Скрипт забирает свежий код из GitHub, применяет новые миграции базы,
пересобирает сайт и перезапускает службу.

## Полезные команды

| Задача | Команда |
|---|---|
| Состояние службы | `systemctl status pvs-mirror` |
| Журнал работы | `journalctl -u pvs-mirror -n 100` |
| Перезапуск | `systemctl restart pvs-mirror` |
| Резервная копия базы | `sudo -u postgres pg_dump pvs > /root/pvs-$(date +%F).sql` |
| Перевыпустить SSL | `certbot --nginx -d reserv.ваш-домен.ru` |

## Если что-то не работает

| Признак | Решение |
|---|---|
| `/health` → `database: error` | Проверьте `DATABASE_URL` в `.env`, выполните `systemctl status postgresql` |
| В админке «Неверный пароль» | `ADMIN_PASSWORD` в `.env` не совпадает. После правки: `systemctl restart pvs-mirror` |
| Лицензия «подпись недействительна» | `OFFLINE_KEY_PRIVATE` отличается от облачного |
| SSL не выпустился | DNS ещё не обновился. Подождите и выполните `certbot --nginx -d домен` |
| Сборка сайта упала по памяти | Добавьте swap: `fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile`, затем повторите `update.sh` |
| `sync_from_cloud.py` → «Облако недоступно» | poehali.dev не отвечает. Зеркало работает на последних скопированных данных |

## Ограничения

- **Десктопная версия (.exe)** проверяет лицензии и обновления по адресам
  poehali.dev: они зашиты в сборку. При аварии десктоп продолжает работать
  по уже активированной лицензии и аварийным PVSO-ключам, так как они
  проверяются без интернета. Новая онлайн-активация в десктопе на зеркало не переключается.
- Скачивание установщика `.exe` идёт по ссылке, которая указана
  в админ-панели (Яндекс.Диск). Это от poehali.dev не зависит.
